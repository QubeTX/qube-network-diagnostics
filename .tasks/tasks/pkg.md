TT;DR: Make the signed, notarized, versionless universal PKG the direct native-installer option and updater target while preserving the legacy DMG for already-released clients; advertise the versionless shell command first.

## Why
The native package is already the real Apple Installer payload. Requiring users and the updater to mount a DMG before opening it adds a container without improving package ownership or trust. The direct package channel must preserve both `nd300` and `speedqx`, exact release identity, Developer ID trust, and the user's most recently chosen install method without stranding the immutable v3.7.1/v3.7.2 clients that request the DMG.

## Plan
Publish the signed/notarized/stapled universal PKG and sidecar as the direct native-installer assets. A receipt-proven `/usr/local/bin` install downloads that exact-tag PKG, verifies its checksum, Developer ID Installer identity, trusted timestamp, stapled ticket, Gatekeeper policy, payload, metadata, and version, then opens Apple Installer directly. Continue producing the signed/notarized/stapled DMG and sidecar for old clients, require its nested package to be byte-identical to the direct PKG, and qualify both containers plus install, takeover, repair, downgrade, failure, and uninstall on fresh hosted Intel and Apple Silicon runners. Advertise the versionless managed-archive shell command first; ambiguous ownership fails safely to the matching direct package and website.

## Impact
The advertised Mac/Linux path remains the versionless shell command, while users choosing a native Mac installer go directly from PKG download to Apple Installer. Retaining both direct-PKG and legacy-DMG sidecars adds two assets to the established 30, taking the canonical inventory to 32. Existing Cargo, managed-archive, and native-package owners remain on their current channels. Public JSON and receipt channel identifiers remain stable. The main risks are stale package receipts, cross-channel duplicates, privileged cleanup, artifact races, compatibility drift between containers, and code-signing drift; all are fail-closed and covered by native hosted matrices before physical testing.

## Acceptance
The direct PKG and compatibility DMG are signed, notarized, stapled, versionless, checksummed, and exact-SHA-attested; the DMG contains the exact direct PKG bytes; `nd300 update` and `speedqx update` preserve the package channel and open the direct PKG; a fresh official PKG safely supersedes proven older ND-300 copies; uninstall removes only package-owned files and forgets the receipt; all 32 assets verify; both native hosted architectures pass; one final direct-update physical-Mac batch passes; docs, ADR, evidence, homepage, and cleanup are complete.
